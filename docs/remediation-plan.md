# Remediation Plan

本文档把 `docs/implementation-review.md` 拆成后续整改项草案。

这不是正式需求，也不是代码设计。它只用于确认整改顺序、依赖关系和每项工作的验收标准。确认后可以再拆成本地整改项文件或 GitHub issues。

## 目标

把当前实现的产品表面收敛到 `docs/project-requirements.md` 定义的范围：

- Task.
- Capture Note.
- Goal Note.
- Reflection.
- System Area.
- Local data status.

优先处理与正式需求直接冲突的行为，再处理核心记录 CRUD，最后处理旧模块和文案。

## 建议整改项

### 1. 只保留版本信息，移除更新检查

**依赖:** 无。

**交付结果:**
System Area 仍然显示当前版本，但应用启动和 System Area 都不再检查远程更新，不再展示下载链接或更新状态。

**验收标准:**

- [ ] 应用启动不会自动请求远程更新信息。
- [ ] System Area 只显示当前版本信息。
- [ ] 用户界面不出现“检查更新”“发现更新”“下载更新”等入口或状态。
- [ ] 核心使用不依赖网络访问。

### 2. 移除备份、导出、导入、恢复宣传

**依赖:** 无。

**交付结果:**
产品界面和用户可见文案不再暗示当前已经支持备份、导出、导入或恢复。

**验收标准:**

- [ ] 存储体积或数据状态提示不再建议导出、备份、导入或恢复。
- [ ] System Area 不展示备份、导出、导入、恢复入口。
- [ ] 用户可见文案不把内部保存保护描述成产品功能。
- [ ] 保存风险仍然可以用普通语言提示，例如“数据可能无法继续保存”。

### 3. 对齐 Capture Note CRUD

**依赖:** 2。

**交付结果:**
用户可以创建、查看、编辑、删除 Capture Note。Capture Note 不再作为默认的任务/目标/习惯/日历等转换入口。

**验收标准:**

- [ ] 用户可以创建 Capture Note。
- [ ] 用户可以查看 Capture Note 列表。
- [ ] 用户可以编辑已有 Capture Note。
- [ ] 用户可以删除 Capture Note。
- [ ] Capture Note 界面不要求用户决定后续处理方式。
- [ ] Capture Note 不暴露转换到任务、目标或其他记录的主要交互。
- [ ] Capture Note 不提供转换为 Task 的入口。

### 4. 补齐 Reflection 删除

**依赖:** 无。

**交付结果:**
Reflection 满足正式需求中的完整 CRUD，用户可以删除已有 Reflection。

**验收标准:**

- [ ] 用户可以从 Reflection 详情或列表删除 Reflection。
- [ ] 删除后该 Reflection 不再出现在过去反思列表中。
- [ ] 删除操作不会影响 Task、Capture Note 或 Goal Note。
- [ ] Reflection 仍可创建、查看单条、编辑、分配到日期。

### 5. 对齐 Goal Note CRUD

**依赖:** 1、2。

**交付结果:**
用户可以创建、查看、编辑、删除 Goal Note。目标区域不再要求 key results、任务链接、进度评分或完成状态。

**验收标准:**

- [ ] 用户可以创建 Goal Note。
- [ ] 用户可以查看 Goal Note 列表。
- [ ] 用户可以编辑 Goal Note。
- [ ] 用户可以删除 Goal Note。
- [ ] Goal Note 界面不暴露 KR 创建、KR 完成、KR 删除或 KR 调度。
- [ ] Goal Note 不生成或链接 Task。
- [ ] Goal Note 不显示进度评分或完成状态。
- [ ] 不需要兼容或迁移旧 OKR/KR 历史数据。

### 6. 断开 Task 与非需求记录的产品联动

**依赖:** 3、5。

**交付结果:**
Weekly Task Board 继续保留当前核心任务能力，但任务创建、编辑、完成不再暴露能力分、KR 或目标归档联动。

**验收标准:**

- [ ] 用户可以在某一天创建 Task。
- [ ] 用户可以编辑、删除、完成、取消完成 Task。
- [ ] 完成的 Task 仍保留在周任务板并有明显完成状态。
- [ ] 用户可以移动 Task 到其他日期。
- [ ] 用户可以在同一天内重排 Task。
- [ ] Task UI 不暴露能力分、KR、目标归档等非需求联动。

### 7. 收敛 System Area 内容

**依赖:** 1、2、3、5。

**交付结果:**
System Area 只承担正式需求要求的功能：模块或功能显示控制、可理解的数据状态、版本信息、短帮助。

**验收标准:**

- [ ] System Area 有模块或功能显示控制。
- [ ] System Area 有用户能理解的数据状态。
- [ ] System Area 有版本信息。
- [ ] System Area 有短帮助信息。
- [ ] System Area 不默认展示反思模板管理、更新检查、备份恢复等非需求功能。
- [ ] 被标记为核心或默认显示的模块与当前正式需求一致。

### 8. 对齐本地数据状态与保存失败提示

**依赖:** 3、4、5、6、7。

**交付结果:**
用户能理解核心记录是否本地保存、保存在哪里、保存了什么；核心记录不能保存时会看到警告。

**验收标准:**

- [ ] 数据状态说明覆盖 Task、Capture Note、Goal Note、Reflection。
- [ ] 数据状态说明使用用户能理解的语言描述本地保存。
- [ ] 数据状态说明给出人能理解的保存位置。
- [ ] 保存失败时用户能看到明确警告。
- [ ] 数据状态检查不再围绕旧模块字段或旧记录关系。

### 9. 收敛核心路径文案

**依赖:** 1、2、3、4、5、6、7、8。

**交付结果:**
核心界面和 System Area 中的用户可见文案符合当前需求，不再延续旧的大而全叙事、调侃文案或概念术语。

**验收标准:**

- [ ] 主导航文案可读。
- [ ] Task、Capture Note、Goal Note、Reflection 相关文案可读。
- [ ] System Area 的版本、数据状态、短帮助文案可读。
- [ ] 不再把旧的宏大叙事、调侃文案或概念术语作为核心界面文案。
- [ ] 不把 PowerShell 输出编码造成的显示问题当作源码乱码处理。

## 建议顺序

1. 整改项 1 和整改项 2 可以立即开始。
2. 整改项 4 可以立即开始，因为它只补齐 Reflection CRUD 的明显缺口。
3. 整改项 3 和整改项 5 应先于 Task 联动清理，因为 Capture Note 和 Goal Note 的边界会影响 Task。
4. 整改项 6 应在 Capture Note 和 Goal Note 收敛后进行。
5. 整改项 7 应在核心记录的产品表面基本确定后进行。
6. 整改项 8 依赖核心记录和 System Area 边界稳定。
7. 整改项 9 应最后处理，避免核心文案收敛被前面的大量 UI 改动反复覆盖。

## 已确认决策

- 整改项 3：Capture Note 完全移除转换，只做普通记录 CRUD。
- 整改项 5：旧 OKR/KR 历史数据不需要兼容或转换。
- 整改项 7：旧模块从产品表面移除，但源码先不删除。
