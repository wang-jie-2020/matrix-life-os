# 设计意图

本文档记录了 Matrix Life OS 的视觉方向——为什么做这些选择，而不只是选择了什么。它不重复 `src/index.css` 中的 token 值；它说明 tokens 背后的设计决策。

## 主题关联

Matrix Life OS 是一个本地优先的个人管理工具。它不是团队项目管理器、云生产力套件或日历替代品。产品服务于一个人对自己记录的安静管理。

「Matrix」暗示结构、网格、终端——一个有序决策的空间。「Life」引入温暖、质地和人的痕迹。视觉方向将这两者并置：一个结构化的、类终端的界面（全 mono 排版、ASCII 边框、方括号按钮、直角），叠加一个古老手稿残片的纹理（低不透明度背景、暖土色调、金色高亮）。

设计不是关于「外观酷炫」；它关于让工具感觉像一个安静的工作空间，一个约束与温暖共存的地方。

## Token 系统设计理由

### 颜色

调色板来自古老手稿和自然颜料：深色羊皮纸背景、暖墨色文字、金色光照亮重要元素。

- `--bg-primary: #16120e` — 深色羊皮纸，不是纯黑。暖底色防止界面读起来像终端黑。
- `--accent-gold: #d3a642` — 唯一的高亮颜色。金色标记活动导航、选中状态和交互反馈。只有一个高亮色意味着用户始终知道往哪里看。
- 辅助色（`accent-success`, `accent-danger`）保持柔和——`#8bbf8f` 和 `#d67770` 低饱和度，不抢夺金色。
- 明暗主题共享同一调色板结构；切换只是反转亮度关系。浅色主题用了更深的金色（`#6f4f13`）以在浅背景上保持可读性。

规则：不要引入超过这三个 accent 颜色的新颜色。如果一个组件需要视觉区分，使用间距、排版权重或边框，而不是另一种颜色。

### 排版

全 mono。这不是疏忽——排版本身就是签名。

- `--font-mono` 是主要的展示和 UI 字体：`JetBrains Mono`，后跟 CJK 等宽回退。
- `--font-reading` 是 body 字体：同样 mono 优先，但调整了回退顺序以优先考虑 CJK 可读性。
- 没有衬线/sans-serif 配对。没有可变字重梯度。一个字体家族承载所有角色。

排版层级使用大小、大小写和粗细，而不是不同的字体家族：

| 角色      | 处理方式          |
| --------- | ----------------- |
| display   | 24px bold         |
| h1        | 18px semibold 大写 |
| h2        | 15px semibold 大写 |
| h3        | 13px semibold 大写 |
| body      | 14px regular      |
| caption   | 12px regular      |
| mono-data | 12px regular mono |

规则：标题必须大写。body 和 caption 不能大写。不要引入新的字体大小；使用现有的 24/18/15/14/13/12 梯度。

### 间距

4px 基础网格，从 `--space-1`（4px）到 `--space-10`（128px）。所有布局间距必须使用 `var(--space-N)` 而非硬编码值。没有例外。

### 圆角

零圆角。没有 `border-radius`，永远没有。滚动条滑块、按钮、输入框、卡片——全部直角。这是结构性的，不是装饰性的：它强化了网格/终端的视觉隐喻。

## Signature

**签名元素是古老壁画残片纹理叠加。**

```css
body::before {
  background-image: url('app://resources/background.webp');
  opacity: 0.08;
  mix-blend-mode: normal;
  filter: brightness(0.5) saturate(0.7);
}
```

一个全出血、固定位置、不可交互的纹理层，覆盖整个应用。它是这个页面会被记住的那一个元素。其余一切——排版、颜色、布局——保持安静和有纪律，让纹理承载个性。

如果纹理不可用（例如资源缺失、性能降级），应用回退到纯色 `--bg-primary` 背景而不带纹理。禁止用纯 CSS 图案或渐变模拟纹理。

## 动效理念

这是一个工具型应用，不是营销网站或游戏。动效仅用于状态转换：

1. **主题切换**（`300ms`）——亮/暗切换的平滑过渡。
2. **页面过渡**（`400ms ease-settle`）——review archive 视图的淡入 + 微上移动画。
3. **交互反馈**（`150ms instant`）——悬停/激活时按钮反转。无 spring、无反弹、无装饰。

规则：不为装饰添加动画。如果一段动画没有向用户传达状态变化，那就去掉。用户拖拽任务？那是交互，不是动画。用户切换页面？那是状态变化。滚动触发、视差、入场序列、打字效果——这些属于营销页面，不属于这里。

已经支持 `prefers-reduced-motion`：当用户偏好减少动效时，所有时长归零。

### 缓动曲线

| token           | 用途                    |
| --------------- | ----------------------- |
| `ease-settle`   | 页面过渡（到达）         |
| `ease-confirm`  | 主题切换、可见性         |
| `ease-instant`  | 悬停/按下/释放反馈       |
| `ease-spring`   | 保留，当前未使用         |
| `ease-reorder`  | 保留，当前未使用         |

## 布局概念

三个顶级区域（Action、Review、System）映射到一个平面导航结构。没有嵌套侧边栏、没有面包屑、没有深度层级。每一个区域都是一个全宽垂直滚动面板。

Action 区域内，Capture Notes、Weekly Task Board 和 Goal Notes 按垂直顺序堆叠。Weekly Task Board 始终在折叠线以上可见；Capture Notes 是顶部入口，Goal Notes 是底部锚点。两侧面板（Capture Notes + Goal Notes）在大屏幕上使用紧凑版式以保持信息密度。

Weekly Task Board 按七列排列（周一至周日），可横向滚动。今天对应的列通过金色边框在视觉上区分。

## AI 默认方案自查

frontend-design 技能指出了三种需要警觉的 AI 生成默认外观：

1. **暖奶油色背景（`#F4F1EA`）+ 高对比度衬线 + 陶土色** — 不匹配。本项目使用深色羊皮纸 `#16120e`，不是奶油色。排版是全 mono，不是衬线配对。高亮是金色，不是陶土色。
2. **近黑背景 + 单一荧光绿或朱红色高亮** — 部分接近但不匹配。`#16120e` 是暖色而非纯黑。`#d3a642` 是暖金色而非荧光色。纹理叠加（signature 元素）打破了纯粹的高对比度极简主义。
3. **报纸式排版（细线分割、零圆角、密集分栏）** — 不匹配。虽然有零圆角和网格布局，但 texture overlay 和 mono typography 产生的是终端/手稿质感，不是报纸编排。

视觉方向在以上三条路径之外有自己的位置。深色暖调 pallette + 全 mono + 古代壁画纹理的组合不是 AI 默认方案。

## 写作约束

- 所有产品 UI 文案通过 i18n keys 提供。组件不得包含内联用户可见文案。
- 必须支持英文（`en`）和简体中文（`zh-CN`）界面语言。
- UI 文案不得翻译、改写或修改用户创建的内容（Task、Capture Note、Goal Note、Reflection）。
- 中文 UI 标签为界面文本，不是新的规范领域术语。规范术语保持英文。
- 按钮使用主动语态、句首大写。标签命名动作，而不是系统内部概念。
- 空状态指明用户可以做什么，而不是描述系统状态。
- 错误说明发生了什么以及如何修复，使用界面的声音而非拟人化语气。错误不道歉。
